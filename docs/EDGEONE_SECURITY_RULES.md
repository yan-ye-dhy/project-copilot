# 邀请制演示的 EdgeOne 入口保护

本文件是阶段二由用户在真实控制台核对和实施的候选配置，不代表已配置。2026-11-03 查询 [Makers 限制与配额](https://pages.edgeone.ai/zh/document/limits-and-quotas)，免费版列出 1 条精准速率限制、4 条自定义规则、基础 Bot 防护及平台级 DDoS 防护。具体匹配字段、组合方式、计数周期和动作以该项目控制台为准；不能把完整 EdgeOne 产品的付费能力当作 Makers 免费版已有能力。

## 一条频控规则的优先用途

推荐匹配本站 `/api/` 下的 POST（若支持方法集合，同时包含 DELETE），按平台直接观测的客户端 IP 计数，候选阈值 20 次/60 秒，超限暂时拒绝 60 秒。它覆盖登录、注册、任务提交、管理员上传、Context 和提案创建，也覆盖确认、拒绝和退出；邀请制正常一轮操作应低于此阈值。上线前用用户实际网络测试同出口 NAT 共享 IP 的影响，根据证据调整。

**GET `/api/jobs/{id}` 的任务轮询不纳入这条写请求计数**；不要把全部 `/api/*` 统一限制到相同低阈值。服务端的业务限额和身份校验仍独立执行，不能依赖浏览器提供的 `X-Forwarded-For` 或自选 header。

如果控制台不能组合方法与路径、不能可靠排除轮询，或该规则不覆盖 Cloud Functions，请先记录截图和实际可选项，不猜测规则表达式；STAGING 准入证据不得标记入口保护已通过。

## 最多四条自定义规则的候选分工

| 优先级 | 目的 | 真实控制台必须核实 |
| --- | --- | --- |
| 1 | STAGING 只允许已批准测试来源进入 API；后端另按账号白名单限制业务 | 是否支持来源 IP 条件；测试者出口可能变化，禁止把代理出口误当客户端 |
| 2 | API 仅允许实际使用的方法 | 以当前 proxy allowlist 为准，确认 GET/POST/DELETE 的实际支持，不误伤预检或平台健康流量 |
| 3 | 写请求 Origin 必须为本站 HTTPS origin | 是否支持 header 精确匹配/缺失判断；后台CLI不经过公网，不能为方便关闭CSRF |
| 4 | 拒绝 `/api/docs`、`/api/openapi.json`、内部服务及不在代理白名单中的敏感路径 | 是否支持多路径组合，不能用会匹配正常 `/api/jobs` 的宽泛模式 |

这些规则是纵深保护；后端和 Cloud Function 本身已有限定路径、来源共享密钥及认证。不要把返回 HTML 的人机挑战直接加到 JSON API 上而未测试，否则前端可能将挑战误判为服务错误。基础 Bot 模式、日志可用性及封禁响应需要由用户在控制台确认。

## 用户必须完成的验收记录

保存无秘密的规则 ID、配置摘要、适用域名/环境、实测日期与截图摘要。测试正常登录及一轮业务写请求、超过阈值的拒绝、正常 GET 轮询不被该规则误限、不同用户/同出口 IP 的影响、直接 Tunnel 缺少共享密钥时被拒，以及关闭入口后的行为。不要在记录里保存 Cookie、密钥或真实 Tunnel 域名。

仅规则存在或开关开启不能证明有效；需要在实际 EdgeOne 站点产生受控请求并验证日志与响应。外层测试未通过时保留 CLOSED；通过且获用户明确授权后才可由发布工具接受 STAGING 的对应证据。
