基于 main `64423ed`（PR #14）增加独立历史对话抽屉，以及任务中心的“删除本地记录”。沿用紧凑古风布局、原创剑客头像、安全Markdown、SSE、50分钟等待及独立工单确认。本轮只有前端、静态构建、测试及文档变化；没有操作演示环境PostgreSQL/Qdrant、容器、Tunnel、已有任务、私有配置或付费模型。

## 3. 使用流程

发送问题后自动形成会话，标题取第一条用户问题前20个Unicode字符，不调用模型生成标题。“新对话”保留原消息；“历史对话”可搜索、返回、重命名或删除，展示Agent/RAG类型及本机创建/更新时间。空白会话不进入列表。默认仅在本页内存保存，刷新后消失。

只有主动勾选“在此浏览器保存历史”并确认风险后，普通正文、最终回答、引用及必要展示元数据才写入IndexedDB。关闭保存会清除该账号的持久记录；“清空本机历史”也会关闭保存并清除该账号的磁盘记录，**当前页面内存会话仍可使用，刷新后消失**，确认框及操作结果均说明这一点。单条“删除对话”会同时移除内存列表及已启用保存时的持久快照。

IndexedDB不是端到端加密。账号隔离是应用展示和查询隔离，不能防止持有设备或同源脚本访问网站存储；共用设备不建议开启，也不要在对话中粘贴密钥。退出清除消息DOM、搜索、身份、Context及内存历史；原账号重新认证后才加载它的持久记录。

## 4. 展示历史与执行权限分离

- 会话只保存用户文字、经过最终成功路径校验的回答及白名单引用。未验证草稿、错误响应、系统提示词、工具原始参数、Cookie、CSRF、Bearer、Context Token及审批指纹都不进入历史存储。
- 返回历史时重新安全渲染Markdown和原文；旧提案卡片只有标题、描述和“仅供查看”说明，无确认/拒绝按钮，也不重新请求审批接口。
- 每次真正切换都清除当前`ContextSession`、任务Context映射及可执行提案；后续用户主动发送时创建新的安全Context。模型history仅来自当前会话的普通消息，历史文本不是授权。
- 有待确认提案、提交不确定或后台任务时先提示风险。正在核实POST提交、尚无job_id时不允许丢弃原提交；停止等待不会中止这个已经可能提交的POST，迟到任务编号仍保存。
- 对已取得job_id的公开任务，切换只停止前端GET/SSE等待；原编号留在任务中心及会话中，不取消Worker、不重发模型。已有同步本机调用在结果确认前不允许切换，避免将断开连接误称为取消。
- 恢复已知任务会回到其原会话；没有会话绑定的旧索引会打开独立“恢复任务”会话，不把旧回答写入当前其他会话。用户取消切换风险提示时不会继续查询或提交。

## 5. 存储和本地删除边界

每账号最多50个会话、每会话50条消息、最近30天、每会话256KiB、快照总量5MiB；仅保留完整消息，不把截断草稿当作完整答案。超长回答只在当前页面显示；到达历史容量后保留最近完整消息，面板提示限制。IndexedDB事务超时/拒绝/空间失败回滚并降级为内存，不使用localStorage保存正文。清理失败时不声称旧数据已删除，可在浏览器网站数据中管理。

多标签页通过账号级持久`revision`协调。读取返回当前版本；自动保存、显式开关和清空都在同一个IndexedDB读写事务里比较版本并递增，旧快照不能覆盖新快照。自动保存不能开启保存；清空保留关闭状态和版本，防止旧标签页复活已删除正文。冲突后本页内容暂留内存，停止持久写入并提示刷新后再保存；不自动合并、不自动重试。仅打开另一个标签页读取不会制造冲突；实际执行过期/非法记录清理才递增版本。

数据库沿用原名称、对象仓库和账号键，版本升为2；旧数据和用户原有开关保留，旧偏好首次读取补`revision: 0`。旧版页面尝试以版本1打开数据库会失败并按原逻辑转入内存，不能绕过新版本检查覆盖数据。版本是本机账号历史元数据，不包含会话凭据，也不恢复审批上下文。

任务中心保留原账号隔离、32条/7天恢复索引。`failed`或`unknown`必须经编号匹配的真实GET核实后才显示“删除本地记录”；二次确认展示完整UUID。删除只移除该账号的浏览器索引并更新计数，不调用DELETE，不改变PostgreSQL、审计、费用、幂等、工单、状态或并发槽。`reserved/running`没有普通删除按钮。隐藏/取消隐藏仍保留；删除恢复索引不会连带删除历史对话。

## 8. 限制与后续核对

这是浏览器本地历史，不是云端同步或后端持久化LangGraph。默认不跨刷新，开启保存也不跨设备/浏览器。清理网站数据、隐私模式或存储被回收可能丢失历史，后台任务和工单不会因此消失。

界面会阻止提交未确认时切换或退出；用户直接关闭标签页或刷新时，前端无法凭空补出尚未收到的job_id。此时不自动重发POST，应先核实原请求结果。已收到的编号继续按原只读恢复流程处理。

审核合并后核对新历史入口和已有任务的只读查询即可；无需为验证样式重复发起付费任务。真实公网SSE、手机软键盘和生产模型未在本轮复测，截图为本机模拟，不冒充新的公网业务验收。
