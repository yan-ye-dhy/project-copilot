# 可复现的面试演示

本演示用于讲清当前界面与执行边界。运行的是实际 EdgeOne 静态构建，API、账号、资料、工单、回答及 SSE 进度来自固定合成 fixture。**没有模型、数据库、Phoenix 或公网调用**，不证明真实检索质量、生产权限或延迟。

## 一条命令启动

前置条件为 Node.js 22 或更新版本；不需要 Python、npm 安装、Docker、密钥或 `.env`。

```bash
node scripts/interview_demo.mjs
```

浏览器打开 http://127.0.0.1:4173/。默认使用合成访客，无需登录；端口已占用时执行 `node scripts/interview_demo.mjs --port 4174`。顶部黄色工具栏一直注明模拟。选择场景会填入问题并设置模式，用户仍需点击「发送」。任意问题都返回所选场景的预写结果，模拟不理解自由文本。

Ctrl+C / SIGTERM 关闭服务并删除本次临时静态目录；启动失败也清理该目录。强制杀进程可能留下系统临时目录。不会写入根目录 `dist`，不会修改已有生产产物，不读取 `.env`，不启动真实服务。

## 3 分钟路线

| 时间 | 浏览器操作 | 可以准确说明的内容 |
| --- | --- | --- |
| 0:00–0:45 | 点「1 · 知识引用」→ 发送 →「查看 1 条依据」→ 打开原文 | 当前 UI 如何把回答与来源并列呈现；原文是合成 fixture，并非本轮真实检索 |
| 0:45–1:45 | 关闭原文弹窗，手机上也关闭依据面板；点「2 · 联合查询与独立确认」→ 发送 | 同一回答含知识、工单、提案三种来源；提案出现时未创建工单 |
| 1:45–2:15 | 滚动到提案卡，点击「确认创建工单」→ 查看已创建工单 | 用户按钮触发独立确认请求；模拟上下文和指纹通过后只增加一条内存工单 |
| 2:15–3:00 | 关闭详情，点「3 · 失败与只读恢复」→ 发送 → 等到 `tool_budget` → 刷新 → 任务中心 →「查询 / 恢复等待」 | 已失败任务仍失败；只读查询原编号，不重复提交。这个「恢复」是恢复查询，不是重新执行 |

讲解开场可用：“这个项目把研发知识检索与工单业务放在同一个工作台。模型能提出动作，但创建工单由后端独立校验和事务控制。现在展示的是离线合成场景，真实模型与数据库证据在另一个历史验收入口。”

## 如何回答常见追问

- **为什么单独确认？** 模型生成提案只是建议。独立接口重新校验身份、执行 Context、不可变内容指纹和有效期，再由数据库事务完成写入；自然语言“确认”不是权限。
- **重连是否会重复执行？** 浏览器按原 job_id 只读 GET/SSE。幂等提交和 Worker 执行是另一层；任务状态为 unknown 时不自动重放。模拟测试证明客户端请求序列，真实并发行为查对应数据库测试。
- **保存聊天是不是保存 Agent？** 不是。IndexedDB 只保存白名单展示内容，默认不开启；没有后端 Graph checkpoint 或跨设备同步。恢复任务也不恢复旧提案权限。
- **如何验证Agent改动？** [30场景合同基线](AGENT_TASK_BENCHMARK_REPORT.md)驱动实际编译图，但模型决策是预设替身；真实模型决策质量须另外测量。[工具观察去重](AGENT_OBSERVATIONS.md)同配置减少24.05%的观察字符，完整来源留在可信状态，不能把字符减少直接宣称为费用改善。
- **Rerank 效果有多好？** 历史开发集 26 道可答题 MRR@5 为 0.897436→0.971154，但 Recall@3 从 1 降到 0.935897；保留集 9 道可答题 MRR@5 为 0.944444→1，Recall@5 都为 1。另有无答案题排除于可答均值。小型自建集不能代表普遍效果或回答准确率。
- **为什么有失败演示？** 失败原因、最终状态与恢复方式也需要可解释。这里人为设定 `tool_budget`；真实失败类型与阶段来自执行端，不能由界面进度动画猜测。
- **现在能直接公开上线吗？** 当前有 Cookie/CSRF/Owner/配额/发布门禁等实现；默认 CLOSED，完整公开验收仍须核对发布清单。离线模拟与截图没有开放权限。

## 重置与隔离

「重置模拟」清空当前 Node 进程的模拟任务、Context、提案及新增内存工单，并回到固定初始资料/工单；同时只移除该合成访客的浏览器任务恢复索引并刷新页面。不会调用真实删除接口、清数据库、改账号或释放生产额度。多个标签页共享这个演示进程，因此重置影响它们的模拟任务。

展示历史默认仅在页面内存；若主动开启 IndexedDB 保存，重置不会清空已保存展示历史。可用现有「清空本机历史」管理它。旧执行编号在重置后返回 404，不绑定到新任务。

服务硬编码绑定 `127.0.0.1`，拒绝非本机 Host 和跨源 Origin，写操作校验同源与模拟控制头/CSRF；未知 API 返回错误，绝不转发上游。没有 `--host`、`--upstream` 或读取环境上游的选项。身份与 Context 校验仅用于演示交互合同，不是生产认证实现；不要反向代理或发布这个服务。当前演示专注三个场景，注册、上传、手工提案等未实现入口会明确返回错误。

## 自动验证与截图

以下为 Codex 自动验证，不登记为用户本人手测，也不是新一轮真实业务验收。

```bash
node --test tests/interview_demo.test.mjs
node --test tests/interview_demo_browser.test.mjs
```

浏览器测试需要仓库测试环境中的 Playwright/Chromium；默认从 `playwright` 包加载。已有环境可指定 `PLAYWRIGHT_MODULE` 和 `PLAYWRIGHT_BROWSERS_PATH`。所有浏览器请求只允许本次 127.0.0.1 来源，外域会被拦截并使断言失败。锁定测试依赖的标准安装命令见仓库 CI 配置。

2026-11-07 定向结果：Node **3/3**、Chromium **2/2**，另有原静态构建回归 **12/12**，合计 **17/17**。浏览器验收分别在 1440×1000 和 390×844 完整操作三个场景，覆盖原文弹窗、SSE 草稿、独立确认、刷新后的失败只读恢复及重置。前端源文件未修改；Node 检查实际产物 API 前缀与应用脚本字节一致、Host/Origin 拒绝、未知路由不代理、错误指纹/Context 拒绝、重复确认只产生一条模拟工单。浏览器核实确认前后工单数 1→2，恢复后 `POST /api/jobs` 总数保持 3。
